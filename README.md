# 孙启涵个人主页 · Excel 内容管理版

保留文学刊物风格、中英文切换和手机适配。所有切页、模块、文字、图片均由两份 Excel 表格生成；无需手工修改网页内容。

## 日常使用：改表格、放图片、提交更新

1. 编辑 `content/网站内容_中文版规范版.xlsx` 与 `content/Website_Content_EN.xlsx`。
2. 将需要的图片放入 `assets/`。
3. 本地预览时，保存表格后刷新网页；GitHub 上提交表格和图片后，工作流自动生成并发布网站。

仓库根目录之外、电脑其他位置的表格修改不会自动同步到网站。请修改上述 `content/` 中的副本，或将修改好的文件替换进去。网站是展示页面，不包含在线编辑 Excel 功能。

## 表格约定

| Excel 中的内容 | 网站上的结果 |
| --- | --- |
| 一个工作表（sheet） | 一个切页 |
| 工作表名称 | 切页名称；默认 Sheet1 显示为“个人信息 / Profile”，其他默认名称采用该页首个模块名 |
| 工作表排列顺序 | 切页导航顺序，第一个是首页 |
| 一列 | 一个模块 |
| 第一行单元格 | 模块名称 |
| 第二行及之后的单元格 | 模块图文内容，按从上到下的顺序显示 |
| 独占单元格的图片文件名 | 显示对应图片 |
| 空单元格 | 自动跳过 |
| 有标题、没有内容的列 | 显示“内容待添加” |
| 空白列 | 自动跳过 |

当前提供的表格都只有一个名为 `Sheet1` 的工作表，因此目前只有一个切页；单页时隐藏页面导航，默认 `Sheet1` 在页面上显示为“个人信息 / Profile”。保留页码和所有模块编号；姓名与照片作为首页主体，其余模块以简洁分栏显示。自定义工作表名称会直接作为页面名称。可以直接将它改名为“关于我”（英文版为“About”），再添加“影像”“文字”等工作表。**修改工作表数量、名称和列数后，网站会自动调整，无需改代码。**

中英文工作表**按排列顺序对应**：第一张对应第一张、第二张对应第二张，名称可以分别使用中英文。建议两份表格保持相同的工作表顺序和数量。模块分别来自对应语言的表格，列数可以不同。若某语言没有对应页，切换时回到该语言第一页，并在构建日志提示。

左上角姓名默认取第一张工作表中第一个文字单元格（不含第一行模块标题），并移除姓名后括号内的拼音。若需单独指定，可以在 `site.config.json` 添加 `"name": { "zh": "孙启涵", "en": "Qihan Sun" }`。

## 图片与图文排版

例如将 `photo.jpg` 放入 `assets/`，在一个单元格中仅填写：

```text
photo.jpg
```

也支持相对路径，如 `assets/photo.jpg`、`assets/travel/京都.jpg`。图片可使用 JPG、PNG、WebP、GIF、AVIF、SVG 或 BMP。**图片要用文件名引用，不要直接嵌入 Excel。**

- 网站保留图片比例，不拉伸、不裁掉内容；宽屏下文字和图片可并排，手机上自动换行。
- 连续文字单元格会组成文字段落；图片保留在所在位置，连续图片可并排。
- 点击图片可放大，按 Esc、关闭按钮或点击遮罩退出。
- 文件名可以包含中文和空格。建议避免同名图片；有重名时使用相对路径区分。
- 引用不存在的图片会阻止发布，并指出工作表、模块和文件名，避免悄悄发布缺图页面。
- 日常图片统一放在 `assets/` 最方便；构建也能识别网站目录内其他位置的图片。

单元格内换行会保留。日期和学历经历建议按普通文本填写，例如 `2022年9月—2027年7月`。支持真实换行和字面量 `\n`。文字按纯文本显示，不执行 HTML 或单元格里的指令。请不要合并用于内容的单元格，也不要使用公式；公式会报错并要求转为文本或数值。Excel 中的数值按存储值显示，自定义日期/数字格式不作为网页样式。

## 本地预览与自动刷新内容

需要 Python 3.9 或更高版本，无需额外安装库。在本文件夹打开终端，执行：

```sh
python3 scripts/preview.py
```

浏览器访问 `http://127.0.0.1:8765`。保存表格或替换图片后，**刷新网页**即可看到更新；不需要重启服务。结束按 Ctrl+C。

也可以只生成一次：

```sh
python3 scripts/build.py
```

然后直接双击 `index.html` 查看。直接双击时显示的是最近一次生成的内容；保存 Excel 后需再次执行构建，或使用上面的预览服务。

## GitHub Pages 发布（与上一版不同）

1. 将本文件夹内的全部源文件上传到 GitHub 仓库根目录。确保包含隐藏的 `.github/workflows/pages.yml`，以及 `scripts/`、`content/`、`assets/`、`site.config.json`。
2. 仓库默认分支设为 `main`。若使用其他分支，在 `.github/workflows/pages.yml` 的 `branches` 中对应修改。
3. 打开 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**。不要继续使用之前的 Deploy from a branch 模式。
4. 提交后，进入 **Actions → Build website from Excel and deploy Pages** 查看进度。也可以点击 **Run workflow** 手动运行。
5. 构建成功后，在 **Settings → Pages** 查看实际网站链接。

以后只需提交更新后的 Excel 和图片，就会自动构建并发布。工作流先验证和生成内容；若图片缺失、表格有错误等，工作流停止，线上保留之前成功发布的版本。

发布内容只有网页和被引用的图片，不包含源 Excel。但如果使用公开 GitHub 仓库，仓库里的 Excel 和其他源文件仍可被访问，请只提交准备公开的内容。

官方说明：[将自定义工作流与 GitHub Pages 配合使用](https://docs.github.com/zh/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## 文件结构

```text
├── index.html                  # 页面入口
├── app.js                      # 自动导航、模块、双语、图片放大
├── styles.css                  # 视觉风格、图文与手机布局
├── site.config.json            # 两份 Excel 的位置
├── site-data.js                # 自动生成，请勿手工编辑
├── content/
│   ├── 网站内容_中文版规范版.xlsx
│   └── Website_Content_EN.xlsx
├── assets/
│   └── photo.jpg
├── scripts/
│   ├── build.py                # 读取 Excel，生成静态网站
│   ├── preview.py              # 本地修改后刷新预览
│   └── test_build.py           # 内容生成与校验检查
└── .github/workflows/pages.yml # 提交后自动发布
```

`gallery.html` 与 `writings.html` 为旧版入口兼容文件，打开后同样显示 Excel 管理的网站；新导航始终来自工作表。新增切页不需要复制 HTML 文件。

如需改表格文件名，请同步修改 `site.config.json`。当前文件名沿用提供的“网站内容_中文版规范版.xlsx”；“网站内容_中文规范版.xlsx”等其他名称也可以通过配置使用。构建脚本会读取这两份配置文件，不依赖绝对路径。
